Appendix A: Cleanup Cheatsheet

Run after finishing, or any time the cluster feels cluttered. On a single-node Minikube, leftover Prometheus/Argo CD/Falco pods will exhaust resources.

iDelete all
kubectl delete all --all -n <namespace>
iiDelete a whole namespace (and everything in it)
kubectl delete namespace <namespace>
# Uninstall all Helm releases in a namespace
iiiRun helm list
helm list -n <ns> -q | xargs -r helm uninstall -n <ns>
ivNuclear option: wipe the entire cluster and start fresh
minikube delete
minikube start --driver=docker --cpus=4 --memory=4096

Appendix B: Common Errors and Troubleshooting

Follows the Juice Shop Trainee design language.
Pod STATUS Most likely cause First commands to run
ImagePullBackOff / ErrImagePull Wrong image name/tag, private registry without credentials, or rate limit kubectl describe pod <p> (read Events)
CrashLoopBackOff App exits/crashes on start (bad config, missing env, failing liveness probe) kubectl logs <p> --previous
Pending No node has enough CPU/memory, or PVC can't bind kubectl describe pod <p>; kubectl get pvc; kubectl top nodes
CreateContainerConfigError References a missing ConfigMap/Secret key kubectl describe pod <p>
0/1 Running but not Ready Readiness probe failing kubectl describe pod <p>; kubectl logs <p>
HPA shows <unknown> No CPU requests set, or metrics-server not ready kubectl top pods; check resources.requests
NetworkPolicy not enforced CNI doesn't support policies (default Minikube CNI) restart with --cni=calico
Service unreachableSelector labels don't match Pod labels kubectl get endpointslices -l kubernetes.io/service-name=<svc> (empty = selector mismatch)

General workflow for any failure: get → describe (read Events) → logs.

Appendix C: What We Did Not Cover (and Where to Go Next)

This guide is a complete spine, but "all of Kubernetes" is bigger than any single lab set. Strong next topics, roughly in order of usefulness:

  1. TLS & certificates: cert-manager for automatic Let's Encrypt certs on your Gateway listeners.
  2. Service Mesh: Istio / Linkerd / Cilium for mTLS, traffic shaping, and L7 observability between services.
  3. Advanced networking: Cilium (eBPF CNI with built-in Gateway API support), and deeper Gateway API features (traffic splitting, header routing, GRPCRoute/TCPRoute).
  4. Storage depth: StorageClasses, CSI drivers, volume snapshots, StatefulSet backups.
  5. Multi-tenancy & quotas: ResourceQuota, LimitRange, hierarchical namespaces.
  6. Operators & CRDs: extending Kubernetes with custom controllers (Operator SDK / Kubebuilder).
  7. Cluster lifecycle: managed clusters (EKS/GKE/AKS), upgrades, version-skew, kubeadm.
  8. Progressive delivery: Argo Rollouts / Flagger for canary and blue-green deploys.
  9. Cost & autoscaling: Cluster Autoscaler, Karpenter, VPA, KEDA (event-driven scaling).
  10. DR & backup: Velero for cluster backup and migration.
  11. Deeper supply chain: full SLSA framework, in-toto attestations, admission with the Sigstore Policy Controller.

A practical capstone: combine the labs into one secured pipeline, Git repo → CI runs Trivy + Cosign signing → Argo CD deploys → Kyverno enforces signatures + PSS → Falco watches at runtime → Prometheus/Grafana observe. That end-to-end loop is production DevSecOps.

Appendix D: Glossary

A quick lookup for every term and tool used in this guide. Where a concept has a full explanation, the relevant section is noted.

Admission controller: code in the API server that inspects an object before it's saved, and can accept, reject, or modify it. The enforcement point for PSA, Kyverno, and signature checks. (Sec. 14)

Argo CD: a GitOps controller that continuously syncs the cluster to a Git repo. (Section 2 Concepts, Lab 10)

CNI (Container Network Interface): the plugin standard that provides Pod networking; also enforces NetworkPolicies. Examples: Calico, Cilium, Flannel. (Lab 14)

ClusterRole / Role: RBAC objects granting permissions cluster-wide / within one namespace. (Sec. 14, Lab 13)

Container runtime: the software that actually runs containers on a node (containerd, CRI-O). (Sec. 1)

Controller: software that watches objects and continuously drives actual state toward desired state. The core pattern of Kubernetes. (Sec. 1, Section 2 Concepts)

Cosign: CLI for signing and verifying container images, part of Sigstore. (Sec. 14, Lab 16)

CRD (Custom Resource Definition): a way to teach the cluster a new object type, used by nearly every ecosystem tool. (Section 2 intro)

CVE (Common Vulnerabilities and Exposures): a publicly catalogued security flaw with a unique ID. Trivy scans for these. (Sec. 14, Lab 11)

DaemonSet: a controller that runs exactly one Pod per node; used for node-level agents like Falco. (Lab 6, Lab 17)

Deployment: the standard controller for stateless apps; manages ReplicaSets, rollouts, and rollbacks. (Sec. 1, Lab 1)

Drift: when the live cluster differs from the desired state in Git; GitOps tools detect and revert it. (Lab 10)

eBPF: Linux kernel technology to safely run small observation programs in the kernel; used by Falco and modern CNIs. (Lab 17, Sec. 14)

Exporter: a small adapter exposing a system's metrics in Prometheus format. (Lab 9)

Falco: runtime security tool that watches syscalls via eBPF and alerts on suspicious behavior. (Sec. 14, Lab 17)

Fulcio: Sigstore's certificate authority issuing short-lived, identity-bound signing certs (enables keyless signing). (Sec. 14, Lab 16)

Gateway API: the modern CRD-based standard for L7 HTTP routing; replaces the frozen Ingress API. Objects: GatewayClass, Gateway, HTTPRoute. (Lab 7)

GitOps: operating model where Git is the source of truth and software continuously reconciles the cluster to match it. (Lab 10)

Grafana: dashboard/visualization tool, usually layered on Prometheus data. (Lab 9)

Helm: the Kubernetes package manager; installs/upgrades/rolls back applications packaged as charts. (Lab 8)

Helm chart / repo / release / values: a chart is a versioned package; a repo hosts charts; a release is one installed instance; values are its configuration knobs. (Lab 8)

HPA (Horizontal Pod Autoscaler): scales Pod count up/down based on metrics like CPU; needs resource requests to work. (Sec. 2.3, Lab 5)

Ingress: the legacy L7 routing object, now frozen; superseded by the Gateway API. (Lab 7)

Kyverno: a YAML-based policy engine / admission controller for validate/mutate/generate/verify rules. (Sec. 14, Lab 15)

metrics-server: lightweight current-CPU/memory collector that powers kubectl top and the HPA. (Lab 5, Lab 9)

Namespace: a virtual partition of a cluster for isolation, quota, and access control. (Sec. 2.1)

NetworkPolicy: pod-level firewall rule; enforced by the CNI. (Sec. 14, Lab 14)

OCI (Open Container Initiative): the open standard for container image format and registries (Docker Hub, GHCR). (Lab 16)

OIDC (OpenID Connect): identity standard that proves who you are via an existing account (Google, GitHub). (Lab 16)

PV / PVC (PersistentVolume / PersistentVolumeClaim): cluster storage / a workload's request for storage. (Sec. 3.1, Lab 4)

Pod: the smallest deployable unit; one or more containers sharing an IP and volumes. (Sec. 1)

Prometheus: time-series metrics database that scrapes and stores metrics; queried with PromQL. (Lab 9)

PSS / PSA (Pod Security Standards / Admission): three built-in security profiles, and the admission controller that enforces them per namespace. (Sec. 14, Lab 12)

RBAC (Role-Based Access Control): least-privilege permissions for users and ServiceAccounts. (Sec. 14, Lab 13)

Rekor: Sigstore's public, tamper-evident transparency log of signatures. (Sec. 14, Lab 16)

ReplicaSet: keeps a desired number of identical Pods running; managed by Deployments. (Sec. 1)

SBOM (Software Bill of Materials): a full inventory of what's inside an image; format e.g. CycloneDX. (Sec. 14, Lab 16)

Service: a stable virtual IP/DNS name load-balancing across a set of Pods. Types: ClusterIP, NodePort, LoadBalancer. (Sec. 1, Lab 1)

ServiceAccount: the identity a Pod runs as, used for RBAC and authenticating to the API. (Sec. 14, Lab 13)

Sigstore: the umbrella project (Cosign + Fulcio + Rekor) for software signing and verification. (Sec. 14, Lab 16)

StatefulSet / Job / CronJob: controllers for stable-identity workloads / run-to-completion tasks / scheduled tasks. (Lab 6)

Supply-chain security: proving deployed software is exactly what your pipeline built. (Sec. 14, Lab 16)

Traefik: a modern reverse proxy / load balancer used here as a Gateway API controller and Helm demo. (Labs 7-8)

Trivy: open-source scanner for image CVEs, misconfigurations, secrets, and SBOMs. (Sec. 14, Lab 11)

End of guide. Tested against Kubernetes v1.36, Helm v4, Argo CD v3.x, Falco v0.44, plus current Trivy, Kyverno, and Cosign releases (2026). Pin all tool/chart versions to specific releases for reproducible, supply-chain-safe deployments.
